# Транскрипт как у Claude Code — что не хватает рендереру

**Составлено:** 2026-08-04 по коду `src/renderer/src/lib/markdown.ts`, `components/MarkdownBody.tsx`,
`components/ToolRun.tsx`, `lib/usage.ts`, `components/ChatView.tsx`.

Цель: транскрипт в Chat Hub читается не хуже, чем в Claude Code — видно, что агент делает,
сколько это стоило и сколько заняло, а разметка не рассыпается.

---

## Что уже есть (в WIP второго чата, не в установленном билде)

Скриншот с голыми карточками `Bash / $ command` — это **установленная сборка**. В рабочем
дереве уже написано лучше:

- `ToolRun.tsx` — сворачиваемая карточка вызова, заголовок из `meta.desc`, чип статуса
  (`running…` / `exit N` / `error`), группировка подряд идущих вызовов в «Ran N commands»,
  свёртка длинного вывода с «N more lines», авто-раскрытие упавших.
- `shared/tool-card.ts` — метаданные карточки (`id`, `desc`, `paths`, `added`/`removed`,
  `exitCode`, `error`) едут через фенс, а не парсятся эвристиками.
- `DiffBody.tsx`, `ChangedFiles.tsx` — дифф и сводка тронутых файлов.
- `md-reasoning` — `<details>` со свёрнутым размышлением.

Это закрывает «не понятно, что агент делает». Дальше — то, чего в WIP **нет**.

## Чеклист: блочная разметка

`splitBlocks()` знает ровно семь видов блоков: `h2`/`h3`, `ul`, code, diff, reasoning, tool, `p`.
Всё остальное падает в абзац как сырой текст.

- [ ] **Таблицы (GFM).** Не поддержаны вообще. `| a | b |` рендерится как параграф с палками.
      Нужен парсер шапки + разделителя `---|---` + выравнивания `:---:`, и `overflow-x: auto`
      на обёртке, чтобы широкая таблица не растягивала колонку чата.
- [ ] **Нумерованные списки.** Регулярка `^\s*[-*✅]\s+` не ловит `1.`, `2.` — пронумерованный
      план агента выглядит как слипшийся абзац.
- [ ] **Вложенные списки.** Отступ съедается `.replace(/^\s*/, "")`, вся вложенность плоская.
- [ ] **Чекбоксы `- [ ]` / `- [x]`.** Агенты пишут ими планы постоянно.
- [ ] **Цитаты `>`,** горизонтальная линия `---`, заголовки `#` и `####`.
- [ ] **Абзац не должен рваться** на строке, начинающейся с `|` или цифры — сейчас условие
      выхода из абзаца не знает ни про таблицы, ни про `ol`.

## Чеклист: инлайн

`Inline()` матчит ровно одну регулярку: `(\*\*[^*]+\*\*|`[^`]+`)`. Жирный и код — всё.

- [ ] **Ссылки `[текст](url)`.** Сейчас показываются сырым синтаксисом. Нужны и голые URL.
- [ ] **Политика открытия ссылок.** Три разных случая, и это продуктовое решение:
      внешний `https://` → системный браузер или Browser-сурфейс; `file://` и абсолютный путь
      → Files-сурфейс; `path/to/file.ts:42` → открыть файл на строке. Последнее — то, за что
      транскрипт Claude Code любят, и у нас для этого уже есть Files и Diff сурфейсы.
- [ ] **Курсив, зачёркнутое,** экранирование `\*`.
- [ ] **`**жирный** внутри `кода`` и наоборот** — текущая регулярка на вложенности ломается.

## Чеклист: код и диффы

- [ ] **Кнопка Copy** на каждом code-блоке и на теле tool-вывода.
- [ ] **Подсветка синтаксиса.** Хотя бы ts/tsx/json/bash/diff. Без внешней либы это заметная
      работа — вариант взять `shiki` в бандл и не тянуть CDN.
- [ ] **Номера строк** в диффе и якорь на конкретную строку.
- [ ] **Перенос длинных строк** в `<pre>` вместо горизонтального скролла всей колонки.

## Чеклист: тайминги и стоимость

- [ ] **Длительность turn'а.** `TurnUsage` несёт только токены и стоимость — `formatUsage`
      выдаёт `$0.01 · 2.4k tok`, а у Claude Code это `2m 9s · 2.4k tokens · thought for 6s`.
      Добавить `startedAt` / `endedAt` в `TurnUsage`, форматтер `2m 9s`, и вывести в `TurnCost`.
- [ ] **«thought for Ns».** Блок `reasoning` есть, длительности размышления нет — её надо
      снимать в адаптере между первым reasoning-событием и первым текстовым дельта-событием.
- [ ] **Живой таймер во время turn'а,** а не только итог после.
- [ ] **Длительность каждого tool-вызова** в шапке карточки (`ToolCardMeta` → `ms`).

## Чеклист: ощущение живости

- [ ] **Курсор стриминга** в конце текущего текста.
- [ ] **Автоскролл с прилипанием к низу,** который отпускает, когда юзер проскроллил вверх.
- [ ] **Skeleton вместо пустоты** между отправкой и первым токеном.

## Кто это может делать

Почти всё выше живёт в `lib/markdown.ts` и `MarkdownBody.tsx` — тех самых файлах, которые
прямо сейчас пишет второй чат. Пока его работа не закоммичена, параллельный агент сюда
заходить не должен.

Не пересекается с ним и может идти параллельно:

- тайминги (`shared/types.ts` → `TurnUsage`, `lib/usage.ts`, адаптеры) — но `adapters/` он
  тоже трогает, так что безопасно только после его коммита;
- политика открытия ссылок в сурфейсах (`lib/surface-store.ts`) — тоже его файл.

Вывод: этот блок ждёт коммита второго чата целиком. Дробить его на лейны смысла нет.
