# Вложенные агенты в транскрипте — что построить

**Составлено:** 2026-08-04, по запросу «хочу так же и лучше внутри приложения».

Речь про то, как Claude Code показывает работу субагента: в основном транскрипте — компактная
карточка с именем задачи, внутри неё свёрнутая сводка вида «Ran 8 commands, read index.ts», а по
клику открывается отдельная панель со всем ходом работы этого агента, с кнопками «назад»,
«развернуть на весь экран» и «закрыть».

Зачем нам: сейчас, когда основной агент запускает несколько параллельных задач, в транскрипте
это либо теряется, либо заливает экран. Нужен подробный отчёт по каждой ветке работы, который
можно открыть и закрыть.

---

## Что для этого нужно

### 1. Модель данных
- [ ] `SessionMeta.parentSessionId` — вложенность сессий. Сейчас все сессии плоские.
- [ ] `SessionMeta.label` — человеческое имя ветки работы («Lane A: signing + single instance»),
      отдельно от заголовка.
- [ ] Роллап статуса: родитель показывает «3 работают, 1 упал», а не только свой статус.
- [ ] Роллап стоимости и токенов: сумма по детям поверх собственных.
- [ ] Файлы: `src/shared/types.ts`, `src/main/session-manager.ts`, `src/main/persistence.ts`.

### 2. Откуда берутся вложенные сессии
Два разных источника, и оба надо поддержать:
- [ ] **CLI сам запустил субагента.** У claude это видно в потоке (события про Task/subagent).
      Парсер должен это распознавать и заводить дочернюю сессию, а не рисовать очередную
      tool-карточку. Файлы: `src/main/adapters/claude.ts`, `adapters/stream-parse.ts`.
- [ ] **Пользователь запустил параллельные лейны из Hub.** Наш собственный диспатч: одна задача
      разбита на N сессий, у каждой свой cwd или worktree. Это смыкается с задачей про worktrees
      из FEATURE-GAP.md — там же лежит и защита от того, чтобы параллельные агенты не дрались
      за одно дерево.

### 3. UI
- [ ] Карточка вложенного агента в транскрипте: имя, статус, сводка «Ran N commands», стоимость,
      время. Визуально ближе к нынешней `ToolRun`-карточке, чем к сообщению.
- [ ] Клик открывает панель с полным транскриптом дочерней сессии. Кнопки: назад к родителю,
      развернуть, закрыть. Хлебные крошки, когда вложенность глубже одного уровня.
- [ ] В сайдбаре дочерние сессии — вложенной группой под родителем, сворачиваемой. Сейчас
      сайдбар знает только два уровня: проект и сессия.
- [ ] Живое обновление сводки, пока дочерний агент работает.
- [ ] Файлы: новый `components/SubagentCard.tsx`, новый `components/SubagentPanel.tsx`,
      `components/Sidebar.tsx`, `components/ChatView.tsx`.

### 4. Чего мы можем сделать лучше
- [ ] **Показывать, какие файлы тронул каждый лейн,** и подсвечивать пересечения между ними.
      У нас уже есть `ChangedFiles` и сбор тронутых путей — данные для этого собираются.
      Именно на пересечении файлов параллельные агенты и ломают друг другу работу.
- [ ] **Diff по каждому лейну отдельно** в Diff-сурфейсе, а не один общий diff репозитория.
- [ ] **Кнопка «остановить лейн»** и «перезапустить лейн с той же задачей».
- [ ] **Сводка волны:** N лейнов, столько-то зелёных, столько-то упало, суммарные токены и время.

---

## Порядок

Это упирается в две вещи из FEATURE-GAP.md, которые лучше сделать раньше: worktrees (иначе
параллельные лейны дерутся за дерево) и тайминги в `TurnUsage` (иначе в карточке нечего
показать, кроме токенов). После них — модель данных, потом UI.
