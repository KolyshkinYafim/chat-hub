# Автономный раннер задач

План. Не реализовано.

Режим, в котором приложение само ведёт пул задач до конца: берёт задачу,
работает, проверяет результат внешней командой, откатывает или паркует, пишет
отчёт и переходит к следующей. Ценность в том, что львиная доля стоимости
задачи — это человек, сидящий рядом и жмущий «продолжай».

## Кирпичи, которые уже стоят

| Что | Где | Роль в раннере |
|---|---|---|
| Board | `.chathub/board.json`, `src/main/surfaces/board.ts` | пул задач, агент уже умеет его править |
| Хуки | `src/main/hooks.ts`, событие `turn_done` | примитив петли: ход кончился → следующий шаг |
| Очередь ходов | `SessionManager.flushQueued` | последовательность внутри задачи |
| Worktree на сессию | `src/main/git.ts`, `createSessionWorktree` | изоляция задачи от твоего чекаута |
| Чекпоинты | `src/main/checkpoints.ts` | откат задачи, ушедшей не туда |
| Скрипты проекта | `src/main/surfaces/scripts.ts` | готовые команды проверки |
| Браузерный MCP | `resources/mcp/browser-mcp.mjs` | скриншот и проверка живого приложения |
| Вопросы агента | `AgentInputRequest`, остров | парковка задачи и уведомление |
| Контекст проекта | `.chathub/context/` | что за проект, чем проверяется |
| Usage-леджер | `src/main/usage-ledger.ts` | учёт бюджета прогона |

Не хватает ровно двух вещей: петли и честного условия остановки.

## Модель задачи

Расширение `BoardTodo`, а не новая сущность — доска уже есть и агент уже умеет
её читать.

```
id            стабильный
text          что сделать
verify        команда, доказывающая результат (или имя скрипта проекта)
status        todo | running | parked | done | failed
result        что вышло: ветка, чекпоинт, статистика диффа, вывод verify
question      заданный вопрос, пока задача в parked
budget        необязательный потолок на задачу
```

`verify` — не пожелание, а поле. Задача без него автоматически завершённой быть
не может: раннер сделает работу и **припаркует её на ревью**, честно пометив,
что доказательства нет. Приложение должно говорить это вслух, а не делать вид.

## Петля

```
пока есть задачи и бюджет:
  взять следующую todo
  worktree под задачу               ← обязательно, не опция
  чекпоинт
  отправить задачу агенту
  ждать конца хода
  если агент задал вопрос → parked, уведомить, СЛЕДУЮЩАЯ ЗАДАЧА
  запустить verify
    прошло  → done, собрать отчёт
    упало   → вернуть вывод агенту, повторить (максимум N)
              после N → failed, лог в result
```

Ключевое: **вопрос паркует задачу, а не прогон**. Иначе один вопрос ночью
останавливает всё до утра.

## Условия остановки

Это ядро фичи. Цикл без внешней проверки — машина по сжиганию денег и
производству уверенного мусора: модель всегда считает, что закончила.

Доверять можно только внешнему:

- `verify` вернул ноль
- потолок бюджета прогона (токены, деньги, время)
- потолок на задачу
- K неудач подряд — значит сломано что-то общее, а не эта задача
- кнопка «стоп», крупная и всегда видимая

## Изоляция и безопасность

- **worktree обязателен**: автономный агент не работает в чекауте, где ты сам
  что-то правишь
- **чекпоинт на каждую задачу** — откат одной задачи не трогает соседние
- **push только по явному согласию**, MR только черновиком, автомерж никогда
- режим разрешений прогона записывается в отчёт: потом видно, чем это делалось

## Отчёт

Отчёт, написанный той же моделью, что делала работу, — самоаттестация. Поэтому
основа отчёта — факты, собранные приложением:

- ветка и чекпоинт
- статистика диффа и список файлов
- код выхода и вывод `verify`
- потраченные токены и деньги из леджера

Рассказ модели «что и почему» идёт **отдельным блоком и помечен как её версия**,
а не как факт.

## Интерфейс

Поверхность «Runner» в доке:

- очередь: что сделано, что идёт, что припарковано, что упало
- текущая задача с живой лентой шагов
- потраченный бюджет против потолка
- **припаркованные вопросы первым экраном** — это то, ради чего ты подходишь к
  приложению
- стоп

## Этапы

**v1 — раннер.** Последовательно, по одной задаче, worktree, чекпоинт, verify,
статус обратно в доску. Уже полезен сам по себе.

**v2 — проверки.** Скриншот как вид проверки через браузерный MCP. Повтор с
подачей вывода упавшей команды обратно агенту.

**v3 — отчёт и MR.** Сводка на фактах, черновик PR через `gh`, описание
изменений со ссылкой на чекпоинт.

**v4 — параллельность.** Несколько задач разом, worktree на каждую, очередь
мержей. Раньше v4 не браться: десять агентов одновременно упрутся в конфликты,
и разбирать их будет человек.

## Чего v1 сознательно не делает

- не работает параллельно
- не пушит и не открывает MR
- не берёт задачу без `verify` в автозавершение
- не трогает твой основной чекаут
- не продолжает после K неудач подряд

## Открытые вопросы

1. Пул задач — вся доска или отмеченная подборка?
2. Потолок по умолчанию: деньги, токены или время?
3. Припаркованный вопрос — только уведомление на острове, или ещё и системное?
4. Прогон переживает перезапуск приложения или начинается заново?
